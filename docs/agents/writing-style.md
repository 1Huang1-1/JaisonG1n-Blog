# JaisonG1n Blog Writing Style

JaisonG1n Blog 的写作风格是：**清晰、证据驱动、有真实开发过程的个人技术写作。** 它记录发生了什么、为何作出选择、哪些地方仍不确定，以及结果会怎样影响后续工作。

这是原创的项目写作规范。不得直接模仿具名作者、博主或出版物的声音、措辞、结构或标志性表达。

## Core Voice

- 描述个人工作、判断和观察时使用自然的第一人称中文；先讲人的目标和问题，再引入术语。
- 一段只承载一个主要观点，用标题组织结构，不靠机械过渡句填充。
- 明确区分已核验事实、测试结果、来源材料、个人观察和建议。
- 说明改动为什么影响维护、可靠性、安全、成本、写作或读者，而不只罗列功能。
- 如实记录问题、失败尝试、取舍和不确定性；不得制造经历或虚构把握。
- 呈现工程判断：约束、可选方案、选择和理由。

## Avoid

- 营销话术、夸张结论、标题党、关键词堆砌和没有证据的“革命性”描述。
- 公式化转折、过度正式的汇报腔、重复标题作为结论，或只列功能不讲影响。
- 虚构排障、基准、反馈、访问权限或使用体验。
- 没有核验、观察或实际影响的新闻改写。

## Content-Specific Style

### Development Daily Report

从当天任务或问题开始，记录初始理解、实际发现、采取的动作、验证证据和下一项具体关注点。写具体过程，不把日报包装成复盘。

### Development Weekly Report

按有意义的主题归纳本周工作，不逐日拼接。说明持久变化、未解决风险以及下周判断所需的信息，保留维护所需的技术上下文。

### Technology And AI Daily Report

只选会影响当前工作或读者的变化。说明哪些已证实、哪些是推断以及值得关注的理由；少量深入内容优于新闻罗列。

### Technology And AI Weekly Report

把事件连接成趋势，同时区分观察到的证据与作者解释。说明对工作流、可靠性、成本、技能或产品选择的可能影响，并标明未定论之处。

### Tutorial, Retrospective, Learning Note, And Opinion

教程先说明真实问题、适用边界、原则和风险，再给出必要步骤、前提与验证点。复盘说明目标、约束、选择、失败、验证和后续变化。学习笔记记录原有误解、改变认识的证据、修正后的理解和小型实践。观点文章要有清晰立场、事实或明确标注的推理，并承认合理反例。

## Titles And Excerpts

- 标题采用具体对象加变化、问题或结果；可读、准确，不承诺超出文章范围的通用答案。
- 摘要用一到两句说明主题、具体上下文和读者价值，不复述标题。
- 标题和摘要不得包含未经支持的主张、秘密、凭据、内部路径或不适合公开摘要的细节。

## Explaining Terminology

首次有意义地使用新术语时，用简明中文说明其在当前问题中的作用，之后保持准确技术名称一致。代码标识符、API 名称和配置名称保持原样，在周围解释效果，不做不一致翻译。

## Evidence And Personal Observations

- 公共事实应标明来源或验证方式；仅写实际观察到的版本、日期、测量和结果。
- 证据不足时说明未知内容，不把合理推测写成事实。
- 第一人称观察应说明它是个人经验，并连接到可执行的经验教训，为不同约束留下空间。

## Style Review Checklist

发布前逐项确认：

1. 内容有明确目的和对读者有价值的理由。
2. 标题具体、适度，并被正文支持；摘要独立说明上下文和价值。
3. 已选内容类型遵循对应风格，标题层级有意义，段落各有一个主旨。
4. 事实、测试、来源、观察和观点可以辨别；术语已用白话解释且命名一致。
5. 版本、行为、性能和结果有真实证据，或已明确限定。
6. 已说明为何重要，并诚实交代相关问题、取舍和不确定性。
7. 不含虚构经历、新闻搬运、具名作者模仿、营销语言或敏感信息。

任一必需项不通过时，修订草稿并保持未发布。
