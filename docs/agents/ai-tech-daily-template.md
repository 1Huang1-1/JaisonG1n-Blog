# AI 科技日报固定模板（Site 规范）

本文件是 `AI 科技日报`（contentType=diary，daily 类型）的唯一生成模板。
基准样例：<https://jaisong1n.com/diary/ai-tech-daily-2026-08-01/>。
以后所有 AI 科技日报必须严格按本模板生成；不允许改用“日期堆叠 + 逐条新闻
平铺”的替代结构。

## 一、整体结构（必须按此顺序）

```text
H1  主题化标题（不含日期堆叠）
导语（3 段以内短段）
    1. 日期 + 一句话总览
    2. 更新时间（Asia/Shanghai）
    3. 今日重心与阅读立场说明
H2  主题章节（按当日事件归组，通常 1 个主题）
    H3  1. 条目标题：一句话观点
    H3  2. 条目标题：一句话观点
    H3  3. ...（每个主题 2–5 条）
H2  值得了解的新名词（3–5 条，每条“术语：一句话定义 + 与今日事件的关联”）
H2  今天的判断（1–2 段，全文综合结论，不是条目复述）
H2  资料来源（官方来源清单，条目格式：机构 + 标题 + 日期）
结尾固定语：如果这篇文章对你有帮助，欢迎分享给更多人！
```

## 二、标题规范

- H1 必须给出“读完全文的收获”，而不是罗列公司名或事件名。
- 允许格式：`AI 科技日报｜<主题判断>`，如
  `AI 科技日报｜DeepSeek 更新之后，模型竞争转向接口、成本与代理边界`。
- 禁止：把日期塞进 H1（`AI 科技日报（2026-08-03）：A、B、C` 这类标题禁止）；
  禁止标题里堆叠超过一个公司/事件名。
- 日期只出现在导语第一段和正文内的“更新时间”行。

## 三、导语规范

- 第一段：`YYYY 年 M 月 D 日 AI 科技日报：<一句话总览>`。
- 第二段：`更新时间：YYYY-MM-DD HH:mm（Asia/Shanghai）`。
- 第三段：说明今日重心（为什么挑这些内容）和阅读立场（例如“均以官方页面
  为准，厂商基准、价格和案例不当作独立第三方结论”）。
- 禁止把“今日要点 + 全部来源核验状态”压成一段超长文字。

## 四、正文条目规范

- 新闻必须按主题归组到 H2 章节下，条目用编号 H3
  （`1. 厂商：一句话观点`），每个主题 2–5 条。
- 禁止：每条新闻一个独立 H2（`一、二、三、四` 的平铺结构禁止）；
  没有 H2 主题、直接用长段落堆新闻也禁止。
- 每条正文只写 1 个主段落（4–6 句），聚焦“发生了什么 + 边界 + 对读者/开发
  者的实际提醒”。需要独立观点时，放进文末“今天的判断”，不要在每个条目里
  追加“官方事实 / 补充观察 / 个人观察”三段式。
- 验证状态只在正文内用轻量标签表达一次（如“第一方”“媒体转述”“未完成
  第一方核验”），不得把完整核验过程、失败抓取说明或长串 URL 写进正文。
- 明确区分已证实事实、推断与个人观点；厂商基准、价格、案例不作为独立结论。

## 五、固定模块

### 值得了解的新名词

- 3–5 条，条目格式：`术语（英文）：一句话定义。与今日事件的关联。`
- 术语优先来自当日正文（post-training、Responses API、model routing、
  agentic AI 等），并保持全文命名一致。
- 禁止为了凑数放与正文无关的术语。

### 今天的判断

- 1–2 段，必须给出跨条目的综合结论（几件事放在一起说明了什么），
  不是逐条复述。
- 判断要落在读者可执行的层面（例如“升级前先确认版本、接口、权限和回退
  路径”），并承认不确定之处。

### 资料来源

- 只列官方/原始来源，条目格式：`机构：标题（YYYY-MM-DD）`。
- 媒体转述仅在所有条目都无官方来源时才补充，并保持清晰标注。
- 正文不出现原始 URL；完整 URL 如需记录，写入独立开发日志，不进入公开正文。
- 结束语固定为：`如果这篇文章对你有帮助，欢迎分享给更多人！`

## 六、禁止清单（对照 08-03 的失败点）

1. H1 日期堆叠 + 事件名罗列。
2. 导语一段塞满“今日要点 + 每条来源核验状态”。
3. 每条新闻独立 H2 平铺（一、二、三、四）。
4. 条目内“官方事实 / 补充观察 / 个人观察”多段式；正文堆 URL 与抓取失败说明。
5. 缺少“新名词 / 今日判断”模块，导致只有信息转述没有增量认知。
6. 任何一段超过 6 句的长难句；无法让读者快速扫读。

## 七、长度与数量约束

- 主题章节：1 个为主，最多 2 个；条目总数 2–5 条。
- 新名词 3–5 条；今天的判断不超过 2 段；资料来源不超过 8 条。
- 全文以“快速扫读 + 有收获”为目标：标题能读结论，判断段能带走观点。

## 八、生成与校验

- 生成后按本模板逐项自检，缺任何固定模块都不得提交/发布。
- 与 `docs/agents/writing-style.md`、`docs/agents/research-policy.md`、
  `docs/agents/diary-workflow.md` 共同生效；模板优先于其他风格偏好。
